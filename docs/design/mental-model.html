§ 1 ─ invariants

6 件永远成立 + 1 候选。

strong invariants · weak style · 跟 vision § 3 兼容契约一体

i · invariant 1

signed op

每次仓库变更带可验证签名。agent 操作必由 controlling human key 兜底签名。

象限studio×a(agent 操作)+ delivery×h(对外签名)

ii · invariant 2

op log

每次状态变更进 append-only op log,O(1) 撤销。invariant 6 immutable 的读端视图。

象限studio×* 全部(每一次 op 都进)· delivery 不直出

iii · invariant 3

portable patch

commit 可序列化成跨 alt 实例的原子 patch · 带签名 + chunk hash + invariant 上下文。

象限delivery×* — 给协作者 / 给下个 agent 都走 patch protocol

iv · invariant 4

workspace

N 个 agent 在同仓并发 · 无全局锁 · 无 index 损坏窗口。每 workspace 独立 working tree。

象限studio×a 主载体 — agent 自由产出的基础设施

v · invariant 5

git compat · L1 语义保真

L1(必)所有 commit / tree / blob / tag git hash 不变 · refs / HEAD / config 还原 · 锚定 VISION § 8.1 拍板。 L2(不追)packfile 布局 / ref 后端(reftable/files)/ loose↔packed 是 git 自由度。

象限delivery×h 主载体 · canonical 字节让 L1 是结构性保证 · 非测试时保证

vi · invariant 6

immutable history

commit oid 永不改 · message 改走 overlay 不动 oid · tree 改 = 新 oid 老 oid 进 op log。唯一例外:emergency scrub(高门槛 + 显式 + 进 transparency log)。

象限全象限 baseline · 跟 invariant 2 op log 一体

vii · 候选 invariant 7

LLM 隔离

core 0 LLM · 4 component(alt-cli / alt-daemon / stones / alt-server)任一 LLM client import = CI grep gate fail。 LLM augmentation 仅在 alt-llm-bridge 独立 plugin · 显式 opt-in。

象限架构 baseline · 等 M18 W1 升正式 invariant 7(plan/M18.md)

§ 3 ─ studio → delivery

七件编辑学职责 · 在出口边界发生。

studio 真实创作态 → delivery polished 阶段成果 · 单向 · 不可逆

studio→delivery 编辑学只在出口边界发生 — 不在 commit 时 · 不在内部 sync 时。 这是让 agent / owner 在 studio 完全自由 · 同时 delivery 永远 polished 的关键架构选择。

# 职责 做什么 push / export 触发

2 message 降级 schema 字段(agent_vendor / session_id / tokens_* / decisions / fix_suggest)全部丢 · 留 type / scope / summary / body / closes。alt://issue/N 解成 #N always
3 path filter alt-only path 整体不出现在 git tree · 同一 commit 在 alt 和 git 两侧 oid 不同(超集 ↔ 子集 映射) always(per visibility rule)
4 author 聚合 ai-agent / bot identity 的 author 字段 → controlling human(claude-a@local → owner@)。可选 Co-Authored-By 留 AI 痕迹 always · 跟 § 25 三类型 identity 一体
5 branch filter wip/* / tmp/* / abandoned task 分支不推 git。git 只见 main / develop / release/* / hotfix/* + 已 finish 的 feature always
6 LFS conversion alt CDC chunk 实体不推 git · 转 LFS pointer · 大文件 backend 走 alt 服务器或独立 LFS server 启用 LFS profile 时
7 secret hard gate 唯一会 reject push 的职责。entropy scan + alt://kind/secret 分类检查 · 任何 secret material 出现在 commit / message / branch name → push 拒绝。CI 端 mirror 同步跑 scan 兜底 always

§ 7.2 · LLM 隔离 · 4 component 边界

§ 7.3 · secret · 四层安全语义

secret 是 studio 一等公民(不属 h/a 维度 · 属 studio/delivery 维度)· 4 层防御:

层机制作用
1visibility = alt-only-secret默认 path 分类(.env* / secrets/ / *.pem)· push --to git 时 path filter 切掉
2仓内加密secret 类 atom 仓内也加密(age / sops 兼容)· 只 controlling human 当前 identity 能解
3server-side ACL.altserver 按 identity ACL · github 公开 / alt-server 限内部
4push hard gatepush --to git 必跑 entropy scan + 显式分类检查 · 检出 secret material → push reject(§ 3 #7)
两层 defense-in-depth 层 1(pre-commit secret-scan · M18 W6)在 commit 前拦 · 友好(指明行)· 0 历史污染。 层 2(push hard gate · § 3 #7)在 push 边界拦 · 严厉(reject + 高 friction)· 兜底层 1 漏。 越晚发现成本越高 · 故意如此 · 鼓励早拦。 同样模式 apply cap-scope check / large-file guard。
